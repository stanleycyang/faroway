# Four-regression follow-up — September 4, 2026

Scope: the four review findings affecting generation recovery, legacy conversion attribution, Expo web booking confirmation, and autocomplete fallback. This is not a claim of universal bug-freedom or production launch approval.

## Fixes and regression coverage

| Finding                                                   | Fix                                                                                                                                                                                                                                                                                             | Verification                                                                                                                                                                                                                             |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Retained draft trip never starts on retry                 | Check the owned trip's generation status before reconnecting. Start the same draft/failed trip; connect to active/completed runs. Recheck 409 responses instead of treating every conflict as successful dispatch. Unknown/unavailable status fails safely without starting a duplicate.        | 429/500 followed by same-trip retry; draft/not-started/failed/error states; active/completed runs; conflicting starts; cancellation during status reads; both polling and SSE paths.                                                     |
| Legacy Booking.com clicks reject signed conversions       | One shared partner normalizer is used by click validation/storage, mobile URL validation, and conversion matching. Normalize the stored legacy value, not the signed payload. Unknown partners and invalid signatures remain rejected; the click URL allowlist is not expanded.                 | Canonical and mixed-case/punctuated booking aliases; wrong partner secret; cross-partner mismatch; malformed identities and inherited-object names; existing idempotent upsert/financial validation tests.                               |
| Expo web booking confirmation silently does nothing       | Use browser confirmation on web and native Alert on iOS/Android. Confirmed web navigation opens the existing GET tracking endpoint synchronously, preserving the browser user gesture; native POST tracking remains unchanged. No navigation on cancellation, invalid URLs or server rendering. | Native confirmation tests; web acceptance/cancellation/invalid-link/SSR tests; actual shared helper in Chromium, Mobile Chrome and Mobile Safari confirmation/popup harnesses.                                                           |
| Google quota/configuration errors erase local suggestions | Validate the provider response. Only valid `OK` and genuine `ZERO_RESULTS` responses succeed; other statuses and malformed data return a sanitized 502. Mobile's existing non-2xx fallback handles it without confusing zero results with failure.                                              | `OVER_QUERY_LIMIT`, `REQUEST_DENIED`, `INVALID_REQUEST`, `UNKNOWN_ERROR`, missing status and malformed predictions; genuine zero results; mapped predictions; mobile local fallback; stale responses, deadlines and caller cancellation. |

Google documents provider error statuses separately from `ZERO_RESULTS` in the [Place Autocomplete response contract](https://developers.google.com/maps/documentation/places/web-service/legacy/autocomplete). The installed react-native-web `Alert` implementation was also inspected and is a no-op. No partner conversion, booking, or paid generation was used to test these fixes.

Before implementation, the added tests reproduced eight web failures and thirteen mobile failures across the reviewed behaviors and adjacent recovery cases. Those tests now pass. TypeScript/React guidance informed explicit recovery actions and shared normalization; browser-testing guidance informed the confirmation and synchronous-navigation checks.
